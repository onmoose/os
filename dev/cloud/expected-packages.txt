# Expected package set for the lean hosted cloud image (dev/cloud/mkosi.conf).
#
# dev/cloud/bootstrap.sh's lean check asserts the built image's package manifest
# matches this set EXACTLY: any package present in the image but not listed here
# (bloat — e.g. the recommends drift of #237), or listed here but absent from the
# image, fails `make build-cloud-image` and the CI cloud-image lane (#238). This
# is the leanness guard the old hardcoded cut list could not give — it catches
# ANY off-list package, not just a named handful.
#
# This is a lockfile: one package name per line, `#` starts a comment. Names
# only — versions are not compared, so a patch/minor bump does not churn this
# file; only a genuine change to the dependency graph does, and that change must
# be reviewed. ENVIRONMENT.md # How the profile is realized governs what the lean
# image carries; the appliance cuts (network-manager, avahi, samba, mergerfs,
# cryptsetup, tpm2-tools) must never appear below.
#
# openssh-server IS in the set (#467), and used to be named above as a package that
# must never appear. That sentence was written when a hosted box had no SSH at all;
# DECISIONS.md 2026-09-09 reverses it. Hosted SSH is a per-account opt-in with a
# public key as the mandatory factor, so the daemon ships — installed and stopped,
# started only while an account has SSH on (BUILD.md # SSH). It brings
# openssh-client, openssh-sftp-server, adduser, ucf, sensible-utils, runit-helper,
# procps + libproc2-0, libncursesw6, libfido2-1 + libcbor0.10, libwrap0,
# libwtmpdb0, libtext-charwidth-perl and libtext-wrapi18n-perl with it; all are
# listed below so the exact-match guard still holds.
#
# nftables is in the set because docker-ce hard-Depends it (#241) — its proper
# fix/decision is tracked there; until then it is part of the lean set, not a
# leak.
#
# grub-common + grub-pc-bin + grub-efi-amd64-bin (+ grub-efi-amd64-unsigned, and
# the transitive libs: dmsetup, gettext-base, libbrotli1, libdevmapper1.02.1,
# libefiboot1t64, libefivar1t64, libfreetype6, libfuse3-4, libpng16-16t64) are in
# the set because GRUB boots the A/B image under both firmwares (#561; #277):
# legacy BIOS (Hetzner CX) and UEFI (CPX), from one grub.cfg and grubenv.
# systemd-boot left the image with #561.
#
# rauc + rauc-service (#561) carry the slot config for the A/B update (#562,
# #563). They bring glib (libglib2.0-0t64, libffi8, libatomic1), json-glib,
# libnl-3, and libcurl3t64-gnutls with its TLS and HTTP stack (libgnutls30t64,
# libnettle8t64, libhogweed6t64, libp11-kit0, libtasn1-6, libidn2-0,
# libunistring5, libpsl5t64, libnghttp2-14, libnghttp3-9, libngtcp2-16,
# libngtcp2-crypto-gnutls8, librtmp1, libssh2-1t64, libldap2, libsasl2-2,
# libsasl2-modules-db).
#
# e2fsprogs (+ libext2fs2t64, libss2, #561) formats and checks the state
# partition at boot; the image had no mkfs.ext4 before.
#
# The concrete kernel-image package (linux-image-<abi>-amd64) is deliberately
# NOT listed: its name carries the ABI version, which changes on every kernel
# bump. The lean check normalizes it out of the diff on both sides; the stable
# meta-package linux-image-amd64 (below) is what guarantees a kernel is present.
#
# Regenerate when a package change is intended: run the lean check (the CI lane,
# or `make build-cloud-image` on a host where mkosi builds) and add the reported
# "UNEXPECTED" names / drop the reported "MISSING" names below.
#
